PART 2 — PROJECT DESIGN PLAN
============================================================

PROJECT NAME
------------
InterviewGraph
(or a similar name selected by the repository maintainer)

ONE-LINE DESCRIPTION
--------------------
An open, structured interview-question knowledge base that maps job descriptions, roles, skills, concepts, projects, and real interview questions to generate evidence-based interview preparation.

CORE IDEA
---------
Build a public dataset first.
Build the ontology/knowledge graph second.
Build JD-to-question retrieval third.
Build prediction/ranking fourth.
Use newly reported interviews as evaluation data.


============================================================
1. PROJECT GOALS
============================================================

Primary goals:
1. Create a high-quality public interview-question dataset.
2. Preserve real interview questions and their provenance.
3. Represent relationships between questions, concepts, skills, roles, companies, and projects.
4. Build a knowledge graph over the interview domain.
5. Given a JD, extract requirements and retrieve relevant questions.
6. Rank questions by relevance and evidence.
7. Generate likely follow-up questions from graph relationships.
8. Continuously evaluate predictions against newly reported interview experiences.
9. Make the dataset useful independently of the prediction system.
10. Keep the project open and community-contributed.


============================================================
2. IMPORTANT PRODUCT PRINCIPLE
============================================================

Do NOT claim:
"These are the questions your interviewer will ask."

Prefer:
"These are questions ranked as relevant based on the job description and the evidence contained in this dataset."

The system should expose:
- source/provenance
- confidence
- observed frequency
- role
- skill
- concept
- difficulty
- question relationships

The system should distinguish observed interview data from generated questions.

============================================================
7. JD PROCESSING PIPELINE
============================================================

INPUT:
Job Description

STEP 1:
Parse JD.

STEP 2:
Extract:
- role
- seniority
- industry
- required skills
- preferred skills
- technologies
- responsibilities
- domain concepts
- architecture/system requirements

STEP 3:
Normalize extracted skills against the ontology.

Example:
"Vector DB" -> vector-database
"Postgres vector search" -> pgvector
"LLM applications" -> llm
"distributed training" -> distributed-training

STEP 4:
Expand graph neighbors.

Example:
RAG
 -> embeddings
 -> vector DB
 -> HNSW
 -> hybrid retrieval
 -> BM25
 -> reranking
 -> evaluation

STEP 5:
Retrieve candidate questions.

STEP 6:
Rank candidate questions.

STEP 7:
Generate follow-up questions from existing graph relationships.

STEP 8:
Return grouped preparation output.


============================================================
8. QUESTION RANKING
============================================================

Initial ranking can be deterministic.

Example conceptual score:

score =
    JD_skill_match
  + concept_match
  + role_match
  + seniority_match
  + observed_frequency
  + company_match
  + graph_centrality
  + project_similarity
  + semantic_similarity

Do not immediately train a complex ML model.

Start with:
1. exact skill matching
2. ontology expansion
3. embedding similarity
4. graph relationships
5. observed frequency

Then learn ranking from real evaluation data.

============================================================

1. Store the JD if legally/publicly shareable.

5. Compare prediction vs reality.

Metrics can include:

Precision@K
MRR
NDCG
Skill coverage
Concept coverage
Follow-up relevance

Also measure:
- hallucinated/unsupported question rate
- percentage of predictions backed by observed data
- novelty rate
- user usefulness rating

---------------
1. Generate edges from structured records.

4. Export graph representation.

PHASE 4 — JD parser
-------------------
1. Accept TXT/Markdown JD.
2. Extract role.
3. Extract skills.
4. Normalize skills.
5. Map skills to concepts.
6. Produce structured JD JSON.

PHASE 5 — Question retrieval
----------------------------
1. Exact skill retrieval.
2. Concept retrieval.
3. Graph-neighbor expansion.
4. Semantic retrieval.
5. Candidate merging.
6. Deduplication.

PHASE 6 — Ranking
-----------------
Implement a transparent baseline scorer.

Do NOT start with a black-box model.

Make ranking explainable:

Question:
"How does reranking improve precision?"

Matched because:
- JD contains RAG
- JD contains retrieval
- Reranking is a child concept of retrieval
- Question has high concept overlap
- Question is observed in interview data

PHASE 7 — Evaluation
--------------------
Create benchmark JDs.

For each benchmark:
- expected skills
- expected concepts
- known questions
- retrieved questions
- ranking results

Add Recall@K, Precision@K, MRR and NDCG.

PHASE 8 — UI/API
----------------
Only after the data and retrieval system are stable.

Build:
POST /predict
GET /questions
GET /skills
GET /concepts
GET /graph
GET /roles
